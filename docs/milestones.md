# 里程碑

来源：[PRD.md](../PRD.md) §6。本文件把验收拆成可勾选清单；实现未开始前只作规划。

**MVP 只验收两件事：压缩率（10%–30%）+ 保真度（硬指标）。**

## M1（1–2 周）— MVP

**目标**：TS 流水线 +（至少）洞 B 打通；3–5 条成功 Trace 上得到剪后版，并完成压缩率 + 保真度盲测。架构见 [architecture.md](./architecture.md)：编排纯代码，LLM 只进 agent 洞。

### 交付

- [ ] 搞原料：3–5 条带「最终做对了」标记的 Trace（优先 SWE-bench；或本地 Claude Code / openclaw session）
- [ ] Admission Gate：无 Ground Truth 拒绝入库
- [ ] L0 适配器 + `segmenter` + `rules`（纯 TS）
- [ ] `orchestrator.ts` 确定性编排（无 LLM、无 LangChain）
- [ ] 洞 B：pi `label_segment` + 3 个以内 skill；未决段 map-reduce；失败窗「保守不裁」
- [ ] （尽量）洞 A 骨架 pass，注入洞 B context；若排期紧可先无骨架打通再补
- [ ] `assembler`：保留关键决策 + 有效探索 + 少量代表性死胡同；删例行；Span 初版
- [ ] 导出剪后版，统计压缩率；SQLite 记下打标结果
- [ ] 保真度盲测：新开对话只喂剪后 Trace；记录通过 / 未通过

### 明确不做（留给 M2+）

- 训练版 / 回放版双格式定型（M1 可先出一份中间剪后 Trace）
- 批量处理
- 训练有效性对比、人类可读性盲读

### 出门门槛

- 至少 3 条剪后 Trace，压缩率落在可讨论区间（目标朝 10%–30% 靠）
- 保真度盲测有书面结论；答不上来的样本要标出是「剪过头」还是「标签错」

---

## M2（3–4 周）— 双产物与门禁

**目标**：Training Cut / Playback Cut 定型；压缩率与保真度达标并成为发布门禁；超长 Trace 打标稳妥。

### 交付

- [ ] Training Cut（SFT 格式）
- [ ] Playback Cut（导演剪辑版，量级约 500→30 步）
- [ ] 超长 Trace 的 map-reduce 逐窗打标再汇总
- [ ] 压缩率稳定落在 **10%–30%**
- [ ] 保真度盲测作为发布门禁
- [ ] 步长跨度约束（够得着）硬化进流水线
- [ ] 规则层覆盖率可度量（LLM 只打模糊段，调用量可解释）

### 出门门槛

- MVP 两硬指标达标
- 双产物同源（同一标签与保留集，见 ADR-0003）
- 工具自身 token 成本明显低于「全量 LLM 打标」基线

---

## M3（后期）— 训练有效性与批量

**目标**：验证剪后 SFT 相对原始 SFT 的效果与成本；补人类可读性；支持批量。

### 交付

- [ ] 剪后 Trace 微调小模型 vs 原始 Trace 微调：效果与成本对比
- [ ] 人类可读性：2–3 名同事盲读，10 分钟内能否复述思路
- [ ] 批量处理入口

### 出门门槛

- 训练有效性结论可复述（含成本）
- 批量路径不依赖手工逐步跑脚本
